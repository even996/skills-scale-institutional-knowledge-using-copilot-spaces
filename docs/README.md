# OctoAcme Project Management Docs

This README is the central entry point for OctoAcme's project management process documents. It provides a quick overview of how the team initiates, plans, executes, releases, and improves work, along with links to the detailed guidance in the `docs/` folder.

## Brief summary of OctoAcme project management processes

OctoAcme follows a customer-first, iterative delivery model with clear ownership and lightweight governance. Work begins with project initiation, where the team defines the problem, goals, stakeholders, success metrics, and a high-level timeline in a Project One-pager. Once approved, planning turns the idea into a backlog with prioritized work, acceptance criteria, resource estimates, milestones, and a documented Definition of Done. These artifacts help align product, engineering, and stakeholders before execution begins.

During execution, the team uses a project board with stages such as Backlog, Ready, In Progress, In Review, QA, and Done. Delivery is supported by daily standups, weekly status reviews, milestone demos, and small pull requests that include issue links and acceptance criteria. CI checks, testing, and at least one review approval help keep work high quality and reduce risk before merge. Delivery roles are clearly structured: Product Managers define outcomes and priorities, Project Managers coordinate timelines and communication, Developers implement and test the solution, and QA validates acceptance criteria and release readiness.

Communication and risk management are built into the workflow. The team tracks dependencies, monitors risks, shares status updates with stakeholders, and escalates issues through a defined path when blockers emerge. Release work follows a standard process that includes pre-release checks, smoke tests, deployment verification, rollback planning, and clear stakeholder communication. After each sprint or major milestone, the team runs retrospectives to capture improvements, assign action items, and feed learnings back into the project backlog and broader process documentation.

## How to use this documentation

- Start with the overview and initiation docs when a new project idea is being evaluated.
- Use the planning and execution docs to manage backlog, milestones, and day-to-day delivery flow.
- Reference the risk, release, and retrospective docs when coordinating stakeholder updates, deployments, or lessons learned.
- Use the issue template in `.github/ISSUE_TEMPLATE/` to propose updates or new content for any process document.

## Maintenance

- Keep the links in this index current when documents are added, renamed, or moved.
